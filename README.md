# PS-Q3: Noise-Resilient Classification & Error Mitigation

**Qiskit Fall Fest 2026 — Phase 1 | Quantum Machine Learning**

This repository implements a small 4-qubit Variational Quantum Classifier (VQC), evaluates it under ideal and synthetic device noise, applies readout measurement mitigation, and compares two participant-defined processor coupling maps.

> **Important:** The numbers in `results/` are generated by running the experiment. Do not invent or manually fill results. This starter repository does not claim a result until you run it successfully.

## Problem statement

Evaluate a trained VQC under ideal versus synthetic device noise and apply at least one error mitigation method on Processor A versus Processor B.

## Official setup reflected here

- Dataset: `make_classification(n_samples=200, n_features=4, n_informative=3, random_state=42)`.
- Binary labels and an 80/20 train/test split.
- Four logical qubits; angle encoding and trainable rotation layers.
- Processor A: 5 physical qubits.
- Processor B: 9 physical qubits.
- Basis gates: `rz`, `sx`, `x`, `cx`.
- Synthetic noise: one-qubit depolarizing `p=0.001`, CX depolarizing `p=0.005`, readout error `p=0.01`.
- Transpilation: optimization level 1, seed 42; 4096 shots.
- Processor B's example coupling map is the 12-edge heavy-hex-inspired reference topology from the guide. Processor A uses the linear-chain reference topology. The guide allows participants to design and justify valid alternatives.

## Method

1. Generate the synthetic dataset and scale features to rotation angles.
2. Train a parameterized 4-qubit circuit with a classical optimizer using exact statevector scores.
3. Evaluate held-out samples on ideal and noisy simulators.
4. Calibrate readout by preparing `|0>` and `|1>` and measuring physical qubit 0.
5. Invert the 2x2 assignment matrix to correct the observed output probability.
6. Compare accuracy, mean transpiled depth, CX count, and estimated SWAP overhead for Processor A and B.

### Important interpretation note

The training objective uses an ideal statevector simulator for a stable, small demonstration. The evaluation uses 4096-shot circuits, with the noisy model and processor coupling maps. Readout mitigation corrects only the final measured output bit; it does not remove depolarizing gate errors. Mitigation is not guaranteed to improve test accuracy on every run.

The circuit is a pedagogical baseline. Because the required basis gate set excludes a native `swap` gate, routing SWAPs are decomposed into CX gates. The reported `estimated_mean_swap_overhead` is a rough proxy based on excess compiled CX count divided by three; it is not an exact SWAP count. State this limitation in your report and, for a stronger submission, use Qiskit's routing-pass metadata or a dedicated routing comparison to count inserted SWAPs directly.

## Setup

Recommended: Python 3.11 in a virtual environment.

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python main.py
```

If PowerShell blocks activation, use Command Prompt and run:

```bat
.venv\Scripts\activate.bat
```

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python main.py
```

The run may take a few minutes because it executes many circuit simulations. If needed for development, reduce `shots` in the processor JSON files, but restore 4096 for the official benchmark.
